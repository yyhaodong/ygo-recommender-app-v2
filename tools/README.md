# tools — 画像検索の検証スクリプト

App の推薦アルゴリズム・データは変更しない、**読むだけ**の検証用スクリプトです。Colab で実行します（`!pip -q install open_clip_torch==3.2.0`）。

| ファイル | 何を確かめるか |
|---|---|
| `image_query_diag.py` | アップロード画像の処理と、カードDBの画像ベクトルを作ったときの処理が一致しているか（同じカードの自分自身との余弦 self_cos、切り出し方の探索） |
| `image_query_validate.py` | `app.py` の画像検索関数そのものを読み込み、前回と重ならない独立サンプルで top-1 / top-5 を測る（`--app app.py`） |
| `text_search_check.py` | CLIP モデル（ViT-B-32 / ViT-B-32-quickgelu）でテキスト検索の候補がどう変わるか |

## 2026-10-16 の結果（データ版 3d53e6c3、独立サンプル 148 枚）

- 原因: カードDBの画像ベクトルは「絵柄部分の切り出し + QuickGELU 版 CLIP」で作られていたが、App はカード全体をそのまま、GELU 版で処理していた。
  切り出し（post）+ QuickGELU に揃えると self_cos の中央値は 0.999。
- 正しいカードが上位 5 枚に入った割合（改修前 → 改修後: QuickGELU・3 通りの切り出し・max 統合）

| 入力 | 改修前 | 改修後 |
|---|---|---|
| 官方のカード全体画像 | 25.7% | 100% |
| 官方の絵柄切り出し | 91.2% | 95.9% |
| 模擬撮影（背景・回転・ぼかし・JPEG 圧縮） | 4.1% | 94.6% |
| 模擬スクリーンショット（固定レイアウト。楽観的な値） | 2.7% | 100% |
| 低解像度のカード全体画像 | 9.5% | 68.9% |

注意: 余弦スコアは識別の確率ではありません。実際のスマホ写真・実際のスクリーンショットでは未検証です。
